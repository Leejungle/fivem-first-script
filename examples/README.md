# fxpreflight examples

This folder contains a deliberately broken `server.cfg` and the exact
output fxpreflight produces for it. Use it as a 60-second sanity
check that the install works on your machine, or read the sample
outputs offline to decide whether fxpreflight catches the kind of
issues your servers actually hit.

## Files

| File | Purpose |
|------|---------|
| [`server.cfg.demo`](server.cfg.demo) | A `server.cfg` that intentionally trips 5 rules (2 CRITICAL, 3 WARNING). Do NOT use as a starting cfg for a real server. |
| [`sample_console_output.txt`](sample_console_output.txt) | Verbatim FXServer console output fxpreflight emits when run against `server.cfg.demo`. |
| [`sample_report.md`](sample_report.md) | The matching `fxpreflight_report.md` written via `SaveResourceFile`. Paste-ready for Discord / Cfx Forum. |

## Findings the demo cfg trips

| Rule  | Severity | Why it fires here |
|-------|----------|--------------------|
| R001  | CRITICAL | Only `endpoint_add_tcp` is declared; the UDP line is commented out. |
| R002  | CRITICAL | `sv_licenseKey "INVALID-KEY"` is too short and contains a hyphen (the allowed alphabet is `[A-Za-z0-9_]`). |
| R004  | WARNING  | `sv_hostname "FXServer, but unconfigured"` is on the known-default list. |
| R005  | WARNING  | `sv_maxclients 5000` is well above the 2048 FXServer cap. |
| R007  | WARNING  | `set steam_webApiKey ""` is empty. The `set`-form is the syntax FXServer's default cfg template uses, and is exactly the case `parser_servercfg` learned to unwrap as part of the v0.1 BUG-001 fix. |

R003 (cfg < 200 bytes) deliberately stays silent: the cfg is ~1.3 KB
so it passes the size sanity check.

## Trying the demo against your installed fxpreflight

> The demo replaces `server.cfg.runtime`, NOT your real `server.cfg`.
> Your real cfg is untouched. The next FXServer boot will overwrite the
> snapshot back to your real cfg via `start.bat`.

1. With your FXServer **already running** and fxpreflight installed:

   ```bat
   copy /Y resources\fxpreflight\examples\server.cfg.demo resources\fxpreflight\server.cfg.runtime
   ```

   (Run from `<server-data>/` -- the same directory as `server.cfg`.)

2. In the FXServer console:

   ```
   fxpreflight
   ```

   You should see exactly the lines in
   [`sample_console_output.txt`](sample_console_output.txt).

3. Restore the real cfg by either:
   - restarting FXServer (which reruns the start.bat snapshot copy), or
   - manually running:
     ```bat
     copy /Y server.cfg resources\fxpreflight\server.cfg.runtime
     ```

## Reading the sample outputs without installing

If you just want to see what fxpreflight would say on a typical
misconfigured cfg, open
[`sample_console_output.txt`](sample_console_output.txt) and
[`sample_report.md`](sample_report.md) directly. They are committed
verbatim from a real run -- no synthetic editing -- and are
regenerated by the project maintainers whenever rules or formatting
change.
